# Hosted in-app notification providers: what they offer Cadence

Research for issue #2. **Findings only, no recommendation.** A later ticket makes the choice.

- **Checked:** 2026-11-25 (pricing pages, docs, npm registry, GitHub API). Pricing and free tiers change often, so re-check them before committing.
- **Scope:** an in-app feed/inbox in a React 19 app with a Node (React Router) server. Users are identified by an integer id in a cookie session. Email is out of scope for now, but adding it later is a criterion.
- **Sources:** each claim links to the official docs, pricing page, npm registry entry or GitHub repo it comes from. Anything I could not confirm from a primary source is marked **unconfirmed**. Statements marked *(inference)* are my reading, not the vendor's words.
- **Candidates:** Knock, Novu, Courier and MagicBell (named in the ticket), plus SuprSend as a comparable option.

## Knock

- **React feed:** `@knocklabs/react` ships prebuilt `NotificationFeedPopover`, `NotificationFeed` and `NotificationIconButton`. It can also be used "in a headless way and bring your own UI" with React hooks ([docs](https://docs.knock.app/in-app-ui/react/overview)). Customisation: a `renderItem` prop for feed cells, `--rnf-` CSS variables, `colorMode="dark"`, or replacing Knock's CSS entirely ([feed docs](https://docs.knock.app/in-app-ui/react/feed)). The peer dependency is `react ^17 || ^18 || ^19`. Version 0.15.1 was published 2026-11-06 ([npm](https://www.npmjs.com/package/@knocklabs/react)).
- **Node SDK:** `@knocklabs/node`, "The official TypeScript library for the Knock API". Version 1.41.1 was published 2026-11-10, Apache-2.0 ([npm](https://www.npmjs.com/package/@knocklabs/node), [repo](https://github.com/knocklabs/knock-node)). Knock's docs show the token helper `signUserToken`, imported from `@knocklabs/node/lib/tokenSigner` ([docs](https://docs.knock.app/in-app-ui/security-and-authentication)). The exact trigger-call signature is **unconfirmed** because the Node SDK docs page I tried returned 404.
- **Identity and browser auth:** The user id goes in the JWT `sub` claim and is passed to `<KnockProvider user={{ id }} userToken={...}>`. With **enhanced security mode** on, Knock rejects client requests that have only the public key and no signed user token. The token is a JWT signed with RS256 using a private signing key from the dashboard. Claims: `sub` (required), plus `iat`, `exp` and optional `grants`. The docs say enhanced security mode is **off by default**, and until it is enabled "a request with your public key can act as any user". The client SDK has an `onUserTokenExpiring` callback for refreshing tokens ([docs](https://docs.knock.app/in-app-ui/security-and-authentication)). Cadence's integer id would be sent as a string *(inference)*.
- **Real-time:** "Our in-app API comes ready with websocket support" ([docs](https://docs.knock.app/in-app-ui/overview)). The React feed has a "real-time socket connection" and an `auto_manage_socket_connection` option ([docs](https://docs.knock.app/in-app-ui/react/feed)).
- **Free tier:** up to 10,000 messages/month, where a message is one message to one user on one channel. Unlimited stored profiles, 30-day log retention, Knock branding cannot be removed. Knock does not hard-cap messages; it contacts you if you go over without a billing method ([pricing](https://knock.app/pricing)).
- **Email later:** A workflow "will contain one or more channel steps" ([docs](https://docs.knock.app/concepts/workflows)). Email providers include SES, Postmark, Resend, SendGrid, SMTP and others ([docs](https://docs.knock.app/integrations/email/overview)).
- **Maintenance and security:** The SDK repos are active: `knocklabs/javascript` was pushed 2026-11-24 (MIT) and `knocklabs/knock-node` was pushed 2026-11-16 ([javascript](https://github.com/knocklabs/javascript), [knock-node](https://github.com/knocklabs/knock-node)). The platform itself is closed source *(inference: no public server repo)*. I found no GitHub security advisories on either SDK repo and none for these packages in the GitHub Advisory Database (queried 2026-11-25).

## Novu

- **React inbox:** `<Inbox />` is a "prebuilt, ready-to-use, and fully customizable UI component" with bell, feed, preferences, tabs and snooze. For a custom UI, `@novu/react` hooks or `@novu/js` provide headless use ([docs](https://docs.novu.co/platform/inbox/overview)). Styling is done with an `appearance` prop (`baseTheme`, `variables`, `elements`, `icons`, `animations`), where `elements` accepts style objects, Tailwind classes or CSS Modules ([docs](https://docs.novu.co/platform/inbox/configuration/styling)). The peer dependency is `react ^18 || ^19`. Version 3.21.0 was published 2026-11-23 ([npm](https://www.npmjs.com/package/@novu/react)).
- **Node SDK:** `@novu/api`, using `novu.trigger({ workflowId, to: { subscriberId }, payload })` ([docs](https://docs.novu.co/platform/sdks/server/typescript)). `@novu/node` is deprecated: "March 20, 2025 marks the end of support" ([npm](https://www.npmjs.com/package/@novu/node)).
- **Identity and browser auth:** The user is identified by a `subscriberId`. In production, HMAC is computed on your server as `HMAC-SHA256(secretKey, subscriberId)` (hex) and passed to the Inbox as `subscriberHash`. When HMAC is enabled and the hash is missing, "the Inbox will not load" ([docs](https://docs.novu.co/platform/inbox/prepare-for-production)). This is a static per-user hash, not an expiring token *(inference from the formula)*.
- **Real-time:** The Inbox manages a "real-time unread count" ([docs](https://docs.novu.co/platform/inbox/overview)). The docs list WebSocket hosts `wss://ws.novu.co` (US) and `wss://eu.socket.novu.co` (EU) ([docs](https://docs.novu.co/platform/additional-resources/security)). That the Inbox uses these sockets is my *(inference)*; the pages do not state it explicitly.
- **Free tier:** $0, with 10,000 workflow runs/month, up to 5 workflows, 2 environments, 3 team members, US/EU data residency and 24-hour activity feed retention. Channels: email, in-app, SMS, chat and push. Self-hosting is offered under Enterprise ([pricing](https://novu.co/pricing)). Whether subscribers are unlimited on Free is **unconfirmed** because the pricing table was ambiguous.
- **Email later:** Email is included on Free ([pricing](https://novu.co/pricing)).
- **Maintenance and security:** `novuhq/novu` has about 40k stars, was pushed 2026-11-25, and released v3.21.0 on 2026-11-24 ([repo](https://github.com/novuhq/novu)). The license is MIT except for the `enterprise/packages` directories, which use a proprietary license ([LICENSE-ENTERPRISE](https://github.com/novuhq/novu/blob/next/LICENSE-ENTERPRISE)). The repo has **41 published security advisories** (2 critical, 9 high, 24 medium, 6 low), 33 of them published in 2026 ([advisories](https://github.com/novuhq/novu/security/advisories)). They include IDOR issues where an Inbox subscriber could read or modify another subscriber's data (e.g. GHSA-32mr-9p6f-cx3x, GHSA-63xr-j3cr-gc9p), stored XSS in the in-app Inbox via `redirect.url` (CVE-2026-75510), SSRF and cross-tenant IDOR. Several apply only to self-hosted setups. The GitHub Advisory Database also lists CVE-2026-125114 (SSRF, high) for `@novu/api` < 3.15.0, fixed in 3.15.0 ([GHSA-4x48-cgf9-q33f](https://github.com/advisories/GHSA-4x48-cgf9-q33f)). Which advisories affected Novu Cloud tenants is **unconfirmed**.

## Courier

- **React inbox:** `@trycourier/courier-react` (React 18+; React 17 uses `@trycourier/courier-react-17`) provides `<CourierInbox />`, `<CourierInboxPopupMenu />`, `<CourierToast />` and `<CourierPreferences />`. Components are themed with `CourierInboxTheme` and similar types, and parts can be replaced with custom rendering. `useCourier()` exposes the client for building your own UI. A separate "headless" mode beyond this hook is **unconfirmed** ([docs](https://www.courier.com/docs/sdk-libraries/courier-react-web)). Version 9.3.6 was published 2026-11-25 ([npm](https://www.npmjs.com/package/@trycourier/courier-react)).
- **Node SDK:** `@trycourier/courier`, "The official TypeScript library for the Courier API". Version 10.3.0 was published 2026-11-24, Apache-2.0 ([npm](https://www.npmjs.com/package/@trycourier/courier), [repo](https://github.com/trycourier/courier-node)). Whether the SDK wraps token issuing is **unconfirmed**.
- **Identity and browser auth:** Your backend calls `POST /auth/issue-token` with the workspace API key, using scopes `user_id:<id> inbox:read:messages inbox:write:events` and an `expires_in`. The browser then calls `signIn({ userId, jwt })`. The docs warn that omitting `expires_in` mints a token that "never expires", that the SDKs do not refresh tokens, and that the user id must be read "from your backend's own authenticated session" ([docs](https://www.courier.com/docs/platform/inbox/authentication)). Minting a token is a network call to Courier, unlike Knock, MagicBell, Novu or SuprSend, where your server signs locally *(inference from the docs)*.
- **Real-time:** `inbox.listenForUpdates()` "opens the WebSocket connection required for real-time updates" ([docs](https://www.courier.com/docs/sdk-libraries/courier-react-web)).
- **Free tier:** The Developer plan is free with 10,000 sends/month. A multi-channel template counts as one send, and test environments count toward the limit ([pricing](https://www.courier.com/pricing)). Whether Inbox is included on the Developer plan is **unconfirmed**, because the pricing page does not say.
- **Email later:** "Add `inbox` alongside other channels in your message's routing" ([docs](https://www.courier.com/docs/platform/inbox/inbox-overview)).
- **Maintenance and security:** `trycourier/courier-web` was pushed 2026-11-25 (MIT) and `trycourier/courier-node` 2026-11-25 (Apache-2.0) ([courier-web](https://github.com/trycourier/courier-web), [courier-node](https://github.com/trycourier/courier-node)). The platform is closed source *(inference)*. I found no advisories on either repo or in the Advisory Database for these packages.
- **Note:** The Courier docs pages contain "Agent Instructions" aimed at AI tools (e.g. install a skill). I treated these as page content and did not follow them.

## MagicBell

- **React inbox:** `@magicbell/react` provides prebuilt `FloatingInbox`, `Inbox`, `InlineNotification`, `UserPreferences`, `ToastContainer` and others. Customisation uses `renderLabel`, `className`, `unstyled`, `ItemComponent`/`ButtonComponent` overrides and `--magicbell-*` CSS variables ([docs](https://www.magicbell.com/docs/libraries/magicbell-react)). Version 1.14.0 was published 2026-07-29 ([npm](https://www.npmjs.com/package/@magicbell/react)). The current docs do not describe headless hooks. An older line exists, `@magicbell/react-headless` ("Hooks to build a notification inbox") and `@magicbell/magicbell-react`, both last published 2026-03-20 ([npm](https://www.npmjs.com/package/@magicbell/react-headless)). Whether that line is still recommended for new projects is **unconfirmed**. The React 19 peer-dependency range for `@magicbell/react` is **unconfirmed** because npm lists no peer dependencies.
- **Node SDK:** `magicbell-js`, with server code imported from `magicbell-js/project-client`. Notifications are created with `client.broadcasts.createBroadcast(...)` ([docs](https://www.magicbell.com/docs/libraries/magicbell-js)). Version 2.0.0 was published 2026-11-25 ([npm](https://www.npmjs.com/package/magicbell-js)).
- **Identity and browser auth:** The user JWT is signed by your backend with the project Secret Key using **HS256**. Claims: `user_external_id` and/or `user_email`, plus `api_key`. The docs' examples use a one-year expiry, and no expiry rules are stated ([docs](https://www.magicbell.com/docs/api/authentication/user)). The React `ContextProvider` takes `token` ([docs](https://www.magicbell.com/docs/libraries/magicbell-react)).
- **Real-time:** "MagicBell maintains a persistent connection to deliver notifications in real-time" ([docs](https://www.magicbell.com/docs/channels/in_app)). The SDK source opens a WebSocket to `wss://ws.magicbell.com` ([realtime.ts](https://github.com/magicbell/magicbell-js/blob/main/packages/magicbell-js/src/realtime.ts)).
- **Free tier:** The Builder plan is $0 with 1,000 deliveries/month and 1 project. Deliveries are counted per channel per user ([pricing](https://www.magicbell.com/pricing)). Which channels Builder includes is **unconfirmed**.
- **Email later:** Email is supported through SES, Mailgun, SendGrid, SMTP and others ([docs](https://www.magicbell.com/docs/channels/email)).
- **Maintenance and security:** `magicbell/magicbell-js` was pushed 2026-11-25. Its license is not an OSI SPDX id; npm says "SEE LICENSE IN LICENSE" ([repo](https://github.com/magicbell/magicbell-js), [npm](https://www.npmjs.com/package/@magicbell/magicbell-react)). I found no advisories.

## SuprSend (additional candidate)

- **React inbox:** `@suprsend/react` offers "Drop-in components" and a "Headless" option. `@suprsend/react-inbox` is end-of-support ([docs](https://docs.suprsend.com/docs/inbox-react), [npm](https://www.npmjs.com/package/@suprsend/react-inbox)). Customisation is through a `theme` prop, among others ([repo docs](https://github.com/suprsend/suprsend-react-sdk/blob/main/docs/in-app-feed.md)). Version 1.6.0 was published 2026-11-17, with peer dependency `react >=16.8` ([npm](https://www.npmjs.com/package/@suprsend/react)).
- **Node SDK:** `@suprsend/node-sdk`, "Suprsend Node SDK to trigger workflow from backend". Version 1.15.1 was published 2026-05-19 ([npm](https://www.npmjs.com/package/@suprsend/node-sdk)).
- **Identity and browser auth:** Inbox auth "has been upgraded from HMAC `subscriber_id` to signed JWT user tokens" ([docs](https://docs.suprsend.com/docs/inbox-react)). With enhanced security mode, the backend signs the token with **ES256** using a dashboard signing key, and the client calls `identify(user.id, userToken)` ([docs](https://docs.suprsend.com/docs/client-authentication)). Expiry handling is **unconfirmed**.
- **Real-time:** The feed holds a socket connection (`socketHost`, `disconnectWhenHidden` options) ([repo docs](https://github.com/suprsend/suprsend-react-sdk/blob/main/docs/in-app-feed.md)). Whether this is a WebSocket specifically is **unconfirmed**.
- **Free tier:** 10,000 notifications/month. Email and in-app are included, and the in-app feed shows SuprSend branding. Batching, digest, user preferences and multi-tenant features are excluded ([pricing](https://www.suprsend.com/pricing)).
- **Email later:** Included on Free ([pricing](https://www.suprsend.com/pricing)).
- **Maintenance and security:** `suprsend/suprsend-react-sdk` was pushed 2026-11-17 and `suprsend/suprsend-node-sdk` 2026-05-19, both MIT. Both have low star counts (2 and 16) ([react](https://github.com/suprsend/suprsend-react-sdk), [node](https://github.com/suprsend/suprsend-node-sdk)). I found no advisories.

## Trade-offs to weigh (not a recommendation)

- **Browser auth model:** Knock, MagicBell and SuprSend use JWTs your server signs locally. Knock's (RS256) and SuprSend's (ES256) are asymmetric, and MagicBell's (HS256) uses a shared secret. Courier issues tokens through an API call to Courier. Novu uses a static HMAC hash per subscriber with no expiry. Knock's protection is **opt-in** (off by default), and Courier tokens never expire unless `expires_in` is set.
- **Free-tier headroom:** Knock, Novu, Courier and SuprSend are around 10k/month. MagicBell's is 1k/month. Novu's free tier also caps workflows at 5 and keeps the activity feed for 24 hours. SuprSend's free tier carries in-app branding and excludes preferences, and so does Knock's.
- **Openness vs exposure:** Novu is the only one with an open-source server (MIT core). It also has by far the most published security advisories, several touching the Inbox and subscriber isolation. The others are closed-source platforms with open SDKs and no published advisories found. That is not evidence of no vulnerabilities.
- **React 19:** It is explicitly in the peer range for Knock and Novu. Courier and SuprSend accept it through open ranges (`>=18`, `>=16.8`). It is unconfirmed for `@magicbell/react`.
- **Identity:** Every provider takes an opaque string user id, so Cadence's integer id would need stringifying *(inference)*.
